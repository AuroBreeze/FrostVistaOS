{
I've been confused for two days in a row about why RISCV works fine when pagination is disabled.

This problem isn't difficult. `ld` loads the kernel into a low memory address and links it to a high address. All functions and static variables are stored at high addresses. However, when `qemu` loads the kernel, it loads it near address 0x8000000 and starts from that location. At this point, the PC is 0x80000000. Because `-mcmodel=medany` was used during compilation, relative addressing is employed, so information is calculated, written, and used based on the current PC value. This is also a valid address in physical memory, allowing the system to run normally.
}

{
Therefore, in the early startup phase of LoongArch, it is entirely possible to design it according to the startup method of RISCV.
}
